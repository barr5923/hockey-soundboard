Connecting music services

← Back to the soundboard

Shared API credentials are managed by the administrator.

Local MP3 files and built-in sounds remain available.

Spotify: get a Client ID

  1. Go to the Spotify Developer Dashboard and sign in with your Spotify account.
  2. Click Create app.
  3. Enter any App name and App description (for example "Hockey Soundboard").
  4. In the app, open Settings and copy the Redirect URI to register in Spotify value. Paste it into the Redirect URIs box in Spotify and click Add. It must match exactly. Spotify requires 127.0.0.1 rather than localhost, so open the app at the same address shown there.
  5. Under Which API/SDKs are you planning to use? tick Web API and Web Playback SDK.
  6. Agree to the terms and click Save.
  7. Open the app's Settings in the Developer Dashboard and copy the Client ID. You do not need the Client secret.
  8. An administrator saves the shared Client ID in Admin panel → Music integrations. Each user then clicks Connect Spotify in Settings and approves access to their own account.

Playing full tracks in the browser requires a Spotify Premium account. While your Spotify app is in development mode, add any other Spotify users under User Management in the dashboard.

YouTube: get an API key

  1. Go to the Google Cloud Console and sign in with a Google account.
  2. Click the project picker at the top, choose New project, name it (for example "Hockey Soundboard") and click Create.
  3. Open YouTube Data API v3 in the API Library and click Enable.
  4. Go to APIs & Services → Credentials.
  5. Click Create credentials → API key. Copy the key that appears.
  6. Recommended: click Edit API key, and under API restrictions choose Restrict key → YouTube Data API v3, then save.
  7. An administrator saves the shared key in Admin panel → Music integrations. The server makes playlist requests without exposing the key to users.

The key lets you import public and unlisted playlists. Private playlists cannot be imported with an API key. Keep the key private; anyone with it can use your daily quota.

Apple Music: server setup

This first stage imports metadata and links from public playlists and exports CSVs. It does not provide soundboard playback or access to private library playlists.

  1. Join the Apple Developer Program and create a MusicKit identifier and private key following Apple's developer-token instructions.
  2. Keep the downloaded .p8 key outside the publicly served soundboard folder. Never paste it into Settings or upload it with app assets.
  3. Install the server dependencies from requirements.txt.
  4. Set SOUNDBOARD_APPLE_TEAM_ID, SOUNDBOARD_APPLE_KEY_ID, and SOUNDBOARD_APPLE_PRIVATE_KEY_PATH (an absolute path to the key) in the server's environment, then restart the server.
  5. Log in as an administrator, enable the integration in Admin, save, and choose Check server setup. This checks local signing configuration; importing a playlist verifies Apple API access.
  6. Paste a public https://music.apple.com/us/playlist/.../pl... link into Music library or Playlist Conversion. The region in the link is used for catalog access.

No Apple Music subscriber sign-in is required for public catalog metadata. Imported cards say Open in Apple Music and are skipped by category playback and autoplay. Private, unavailable, and region-restricted playlists report an error rather than saving a partial import.
